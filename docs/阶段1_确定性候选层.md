# 阶段 1：确定性候选层

阶段 1 在不调用 Agent 的前提下，把不可变快照转成可重复的候选发现结果。正式入口仍是 `ScreeningWorkflowService.run_snapshot_screening()`；数据边界仍由 `DataSnapshotManifest` 和字段级事实质量闸门负责。

## 执行边界

`screen_factor_snapshots(..., candidate_mode=True)` 依次执行；V1 因子快照 schema v16 增加 `report_date`，避免质量 Lens 用行情日期冒充财务报告期：

1. 股票名称和 ST/退市排除；
2. QuerySpec 转换后的确定性资格过滤；
3. 技术、财务、行业等客观字段检查；
4. `quality_research`、`trend_observation`、`event_verification` 三个 Candidate Lens 匹配；
5. Lens 内部按客观字段和代码稳定排序；
6. 输出候选理由码、缺失/过期字段、快照 ID、字段来源和候选摘要哈希。

候选层不调用 `professional_formula.py`，不使用总分或 AI 排名。`local_score` 只在旧兼容入口保留，正式候选结果为 `None`。事件 Lens 从快照事实读取标题、日期、来源和 `available_at`；没有事件事实时标记 `insufficient`，未来可获得事实或未验证事实不会伪装成当前证据，也不会阻断其他 Lens。

## 结果字段

每个 `ScreenCandidate` 的正式候选字段包括：

```text
code / lens_ids / eligibility_status
reason_codes / missing_fields / stale_fields
data_snapshot_id / candidate_digest / fact_sources
```

`score_breakdown["candidate_contract"]` 保存同一组字段，供旧结果表和 SQLite 审计层读取；其中不包含专业公式分数。

## 质量闸门

- `blocked` 快照不执行正式候选层；
- `partial` 或 `unverified` 快照不能签发 formal 凭证，只能进入明确标记的复核路径；
- `main_5d_yi` 等未包含在本地因子快照的字段不能按零处理，正式候选层会阻断并列出缺失字段；
- 字段来源从不可变快照事实的 `source/source_version/source_route` 读取；没有绑定事实时只标记兼容数据源，不宣称 PIT 来源。
