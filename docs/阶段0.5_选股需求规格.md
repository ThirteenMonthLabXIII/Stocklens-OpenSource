# 阶段 0.5：选股需求规格与 A 股规则冻结

本文件是《A 股五 Agent 多维证据与候选发现系统迁移计划》的正式补充。阶段 0.5 完成前，不扩展新的预测能力、不恢复公式总分、不允许 AI 直接生成交易结论。

## 1. 冻结对象

生产筛选必须同时绑定以下四个版本化对象：

```text
UniverseProfile v1
LensPolicy v1
PriorityPolicy v1
MissingDataPolicy v1
```

生产入口还必须记录 `mode`、`universe_id`、`universe_version`、`selection_policy_version`、数据快照 ID、`availability_cutoff`、理由码和候选 digest。

## 2. UniverseProfile

正式研究母池为 `a_share_all`，包含四个独立的 `BoardProfile`：`main_board`、`chinext`、`star_market`、`beijing`。

每个板块独立绑定：`exchange`、`listing_rule_version`、`trading_calendar_version`、`price_limit_rule_id`、`liquidity_policy_id`、`technical_policy_id`、`industry_policy_id` 和 `effective_at`。即使数值相同，也不得隐式复用主板规则。

所有模式均不得把以下股票作为正式研究候选：ST/*ST、退市整理、已确认退市、代码无效、股票状态未知、快照身份不完整、`available_at > availability_cutoff`，以及停牌且没有有效价格的股票。探索模式可以展示待处理状态，但 `exploratory_only=true`，不进入正式候选、观察或绩效。

上市年龄按有效交易日计算：Formal 至少 120 日，Exploratory 至少 20 日。流动性窗口为 20 个交易日：Formal 要求有效成交日和价格成交量可用日均至少 15 日、成交额中位数至少 2000 万元；Exploratory 对应为 10 日、500 万元。样本不足必须是 `insufficient`，不得用 1～2 天资金流推断连续行为。

涨跌停不直接排除股票，事实中保存 `price_limit_locked`、`price_limit_direction`、`price_limit_rule_id` 和规则版本。趋势 Lens 另要求最近交易日未锁死且 20 日锁死不超过 3 天；不满足时仅将趋势观察标记为 `insufficient`。

趋势只允许使用同一调整口径的调整后价格序列，并保存原价、调整价、调整因子、公司行为事实 ID、调整方法和版本。缺少调整因子、混用原价/复权价时，趋势 Lens 为 `insufficient`。

## 3. LensPolicy

首批 Lens 固定为：

| Lens | Formal 核心规则 | Exploratory 核心规则 |
|---|---|---|
| `quality_research` | ROE_TTM≥8%；最近 4 期至少 3 期可验证，净利润/经营现金流为正至少 3/4；最新报告不超过 365 日 | ROE_TTM≥0%；最近 4 期至少 2 期可验证，净利润为正至少 2/4；现金流缺失只能保留为不足证据 |
| `trend_observation` | 20 日价格/成交量有效日≥15；20 日趋势≥3%；60 日趋势≥0%；行业相对强度≥0；成交额中位数≥2000 万元 | 对应有效日≥10；20 日趋势≥0%；成交额中位数≥500 万元；行业相对强度缺失可展示但必须标记不足 |
| `event_verification` | 事件距 cutoff≤30 个自然日；`available_at≤cutoff`；代码明确；一级来源、来源路由已验证且可去重 | 事件距 cutoff≤90 日；一级/二级可展示；二级为 `partial`，三级只能待核查 |

质量 Lens 对银行、保险、证券使用金融专用字段；地产、公用事业使用行业分位数；其他行业同时检查绝对负债率和行业分位数。行业样本少于 20 家不能计算可靠分位数，Formal 为 `insufficient`。行业比较必须绑定分类 ID、分类版本、行业代码、生效时间和 `peer_set_digest`。

## 4. MissingDataPolicy

字段分为 `critical_fields`、`supporting_fields`、`optional_fields`：

- Critical 缺失：Formal 不能 `matched`，为 `insufficient`；Exploratory 可展示但保持 `insufficient`。
- Supporting 缺失：保留 Lens 结果，降低优先级并显示缺口。
- Optional 缺失：状态不变，只显示 `unavailable`。

禁止 `None→0`、`NaN→0`、未知行业归入普通行业、缺失现金流改为中性、缺失事件改为无风险、Agent 失败改为 neutral。必须保留 `missing_fields`、`stale_fields`、`unverified_fields`、`blocking_fields` 和 `reason_codes`。

## 5. 候选状态与优先级

Formal Lens 的确定性结果按以下规则生成：至少一个 Formal Lens matched 且基础闸门通过为 `candidate`；关键字段缺失为 `insufficient`；有效证据冲突为 `conflicted`；超 freshness window 为 `stale`；明确违反资格为 `excluded`。只有 `human:<id>` 或 `user:<id>` 可以把 `candidate` 加入 `watch`。

展示层固定为：重点研究、一般候选、证据不足、存在冲突、过期候选。优先级使用离散字段的可解释词典序，不跨 Lens 合并，不产生综合分或综合排名。Lens 内排序字段必须来自固定白名单，股票代码为最终稳定键。

正式流程禁止产生以下字段：

```text
combined_score
overall_score
cross_lens_rank
ai_confidence
final_rating
```

## 6. Exploratory Agent 边界

Exploratory Agent 发现输入候选之外的股票时，只能生成 `ExploratoryProposal v1`：

```text
proposal_id
code
proposed_lens_id
source_run_id
evidence_refs
proposal_reason
missing_evidence
status=pending_human_review
```

处理顺序固定为：Agent 提议 → 人工复核 → 重新执行 Universe 闸门 → 重新执行 Formal Lens → 人工确认后才可进入正式候选。未经该流程不得进入 `CandidateState`、`watch` 或正式绩效。

## 7. 实现边界

规则实现位于：

```text
stock_tool/core/universe_policy.py
stock_tool/core/selection_policy.py
stock_tool/core/priority_policy.py
stock_tool/core/missing_data_policy.py
```

`candidate_lens.py`、`screener_engine.py`、`screening_workflow.py` 和 `candidate_state.py` 继续提供既有阶段 0/1/5 兼容入口；新策略通过 `SelectionPolicy` 作为可替换边界接入。`professional_formula.py` 和 `trade_ai.py` 仅保留兼容读取，不进入新 Formal 策略路径。五 Agent 仍只能消费已冻结的证据包；`evidence_summary.py` 不生成候选、优先级或分数。

阶段 0.5 通过的最低条件是：四板块具有独立规则身份；Formal/Exploratory/Review-only 隔离；三个 Lens 有字段、阈值、排除和缺失策略；PIT、复权、涨跌停、停牌、新股和流动性有测试；行业版本和 peer digest 可追溯；没有跨 Lens 总分；排序白名单固定；探索结果不能直达正式候选和绩效；同一快照可稳定重放相同候选 digest；旧公式可兼容读取但不进入新 Formal 流程。

真实数据源检查另行运行 `python tools\release_acceptance.py --live`，并单独记录网络、限流、权限、代理和源切换风险。
