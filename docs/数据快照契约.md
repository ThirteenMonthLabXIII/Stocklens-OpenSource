# 数据快照契约

阶段0的字段级 `Fact v1`、`CandidateLens v1` 和 `AgentResult v1` 冻结规则见[阶段0_契约冻结.md](阶段0_契约冻结.md)。本文件继续负责不可变快照、事实可获得时间和质量闸门；不要把当前因子缓存直接当作正式 Agent 事实。

## 目的

`factor_snapshots` 是当前因子缓存，不是历史事实数据库。它允许按股票覆盖旧值，因此不能单独用于证明回测或正式筛选所使用的数据在当时已经可获得。

`stock_tool.core.data_snapshot` 提供不可变的 `DataSnapshotManifest` 和 `DataSnapshotFact`：

- `effective_at`：事实实际发生或适用的时间；
- `available_at`：系统实际能够获得该事实的时间；
- `source`、`source_version`：数据来源和来源版本；
- `source_route`：主源、备用源或其他明确路由；
- `revision_id`、`raw_hash`：修订追踪和内容校验；
- `facts_digest`：整个事实集合的内容摘要，避免相同元数据下不同事实集合复用同一快照身份；
- `snapshot_id`、`availability_cutoff`：一次研究或筛选运行使用的数据边界。

## 使用规则

1. 事实的 `available_at` 不得晚于所属快照的 `availability_cutoff`。
2. 快照清单和事实表只允许追加，数据库触发器会拒绝更新和删除。
3. 旧 V1 因子缓存继续用于兼容入口，但新研究、PIT 回测和正式筛选应逐步改为传入 `data_manifest`。
4. `data_manifest` 的数据源必须与筛选运行的 `data_source` 一致。
5. 数据质量为 `blocked` 时，正式筛选必须阻断；`partial` 或 `unverified` 只能进入明确标记的研究或复核状态。
6. `ScreeningWorkflowService` 支持 `require_data_manifest=True`；启用后，正式筛选没有 manifest 会直接阻断，不得回退到当前缓存。
7. Qt 正式筛选已启用该门槛；旧库需要先执行“更新筛选快照”，历史复核仍可读取兼容缓存。

## 迁移边界

本阶段只增加持久化契约和筛选工作流的显式绑定，不自动把旧缓存伪装成 PIT 事实。数据刷新适配器必须先提供真实的字段级可获得时间和来源版本，才能写入新的事实表。

## 刷新事件与幂等写入

`snapshot_ingestion_events` 记录每次刷新尝试，`refresh_event_id` 每次都唯一；它与内容寻址的 `snapshot_id` 分离。刷新失败仍保留事件，但不得产生成功快照。相同规范化事实重试时复用已有快照，并保留新的刷新事件。

`DataSnapshotStore` 的公共入口为：

- `record_refresh_attempt(...)`：先登记请求截止时间、股票池版本、数据源策略版本和来源路由；
- `finalize_refresh(event_id, facts, ...)`：成功/部分成功时原子写入快照并回填事件，失败时只结束事件；
- `get_snapshot(snapshot_id)`：读取不可变清单和事实；
- `resolve_snapshot_for_cutoff(cutoff, universe_id)`：只从满足可获得时间和质量要求的历史快照中解析；
- `assess_snapshot_quality(snapshot_id, contract)`：按声明字段检查缺失、未验证事实和越过 cutoff 的事实。

备用源必须显式记录 `source_route=failover` 或 `used_failover=true`。这不等于自动获得 `verified` 资格；源本身不能提供可靠公告时间时，仍只能使用 `partial` 或 `unverified`。

## AI 研究讨论边界

`stock_tool.core.research_discussion` 只接受绑定 `data_snapshot_id`、`refresh_event_id` 和 `formula_version` 的证据包，最多输入 30 名规则候选。输出严格限定为支持证据、反对证据、因子冲突、数据疑点、事件风险、继续观察条件和数据完整度；未知字段、交易指令、目标价、收益承诺和仓位字段均会使 AI 结果失败。AI 失败不改变规则筛选结果。
