# 选股闭环设计

本文说明本项目从“筛选 + AI 点评”升级到“不可变快照 → 数据质量闸门 → CandidateLens 候选 → 五 Agent 证据 → F/G 层 → 人工观察 → 到期结算与复盘”的闭环方式。专业公式只保留为历史兼容数据；所有结果只用于候选股研究、观察和复盘辅助，不构成投资建议，不承诺收益、胜率或预测准确率。

## 目标

- 每次筛选完成后留下可追踪的 run context，而不是只展示一次性列表。
- 对 Top N 候选自动创建 3/5/10/20 日观察样本。
- 到期后只用真实可得价格窗口结算，缺价格、缺基准或缺行业数据时记录数据质量，不编造收益。
- 按策略、周期、市场状态、行业和权重版本复盘战绩，帮助用户知道哪些结论可靠、哪些需要继续验证。
- 五 Agent 只能整理证据、缺口和冲突；exploratory 建议必须进入人工待审队列，不能直接修改候选集合、排序或观察状态。

## 术语

- 候选股：筛选引擎或 MVP 闭集模板命中的研究对象。
- 观察样本：候选股在某次筛选运行中的固定快照，绑定入选日期、周期、排序、分数和数据质量。
- 策略版本：保存策略或模板配置的可追溯版本。
- run context：一次策略运行的上下文，包括市场状态、权重版本、生效权重和数据质量说明。
- 结算：观察样本到期后计算收益、沪深300超额、最大回撤、MFE/MAE 和评级。
- 战绩：已结算样本在不同分组下的统计结果。
- 影子权重：AI 或研究台提出但未生效的候选权重，只能进入 `shadow` 状态。
- 数据质量：结算时的缺口标记，例如 `missing_price`、`missing_benchmark`、`missing_industry`。

## 当前落地点

- `stock_tool/core/performance_loop.py`
  - `PerformanceStore` 保存市场状态、权重策略、run context、观察样本和结算结果。
  - `ObservationSettlementService` 结算到期样本，缺价格时输出 `missing_price`，不生成伪收益。
  - `ClosedLoopDashboardSnapshot` 汇总今日待结算、近 60 日表现、强弱策略、数据缺口、shadow 策略和下一步建议。
  - `validate_weight_candidate_output()` 拒绝样本不足 30、单维度调整超过 0.05、包含买卖指令或收益承诺的 AI 权重候选。
- `stock_tool/core/v1_database.py`
  - schema v9 包含 `market_regime_snapshots`、`weight_policy_versions`、`strategy_run_contexts`、`observation_samples`、`observation_outcomes`、`ai_decision_logs`。
- `stock_tool/ui/qt_workbench.py`
  - Qt 观察与复盘页展示闭环驾驶舱。
  - 筛选完成后自动记录执行、保存 run context，并为 Top N 候选创建 3/5/10/20 日观察样本。
  - CandidateLens 确定性筛选后自动运行五 Agent；Agent 证据摘要不会回写候选资格、排序或观察状态。

## 数据边界

默认链路使用东方财富公开源、本地 PIT 数据和缓存。Tushare 只作为用户自带 token 后的可选增强源，用于补充资金流、复权或更细历史数据；未配置、未启用、权限不足或网络失败时，不影响免费主链路。

结算口径优先使用 PIT 价格库，必要时读取历史 K 线缓存或接口。若窗口不足，必须标记数据缺口，不得把缺失数据当作 0 收益或成功样本。

## AI 边界

- AI 文案必须使用“候选、观察、复盘、验证、影子策略、数据缺口”等表达。
- 禁止输出直接买入、卖出、必涨、稳赚、收益承诺或准确率承诺。
- AI 权重候选只能写入 `weight_policy_versions(status='shadow')`。
- 样本数不足 30 时，AI 调权候选必须被拒绝。
- 单维度调整超过 0.05 时，候选必须被拒绝。
- active 权重只能由人工确认后的显式流程修改。

## 闭环驾驶舱

驾驶舱面向普通用户回答六个问题：

- 今天有没有到期样本需要结算。
- 近 60 日样本量、已结算数量、上涨比例、跑赢沪深300比例和平均超额。
- 哪个策略近期最强、哪个策略近期最弱。
- 数据缺口有多少，缺口类型是什么。
- 当前 AI 模型费用提示是什么。
- 是否存在 shadow 策略，以及下一步应该先结算、补数据、累积样本还是复核影子策略。

这些信息是复盘入口，不是交易指令。

### 阶段 2：AI 复盘与历史兼容

已落地安全底座：

- 保留旧 AI/公式数据的历史读取和安全校验。
- 新流程不创建、启用、shadow 或回滚专业公式。
- 五 Agent 失败不改变 CandidateLens 候选。

### 阶段 3：复盘科学化与 AI shadow 调权

已落地安全主干：

- formal、review_only、exploratory、legacy 独立统计；正式绩效不读取专业公式状态，也不把 AI 置信度当作表现指标。
- 五 Agent 只整理同一快照证据；失败、缺失、冲突和无效引用保留在 F 层，不改变确定性候选集合、排序或 G 层人工观察状态。
- 专业公式表、权重范围和治理审计只作为历史兼容数据读取；新流程没有启用、shadow、回滚或公式替换动作。

### 筛选执行契约

Qt 条件选股使用 `stock_tool/core/screener_presets.py` 中冻结的八张 v1 模板。模板的结构化硬条件、风险条件、Lens 优先级、客观排序字段、必需字段和缺失策略共同构成执行契约；自然语言仅用于展示。筛选运行同时记录条件哈希、不可变快照 ID/日期、数据状态、`candidate_lens.v1` 和模式。新候选 `local_score` 为空，不能传入专业公式，也不能以公式作为失败回退；过期快照只允许 `review_only` 历史复核，关键字段无法验证时不得生成正式候选或观察样本。

筛选完成后自动按最多 30 只候选分批构造证据包并运行五 Agent。证据包先持久化再检查 API Key；缺 Key 记录 `skipped/missing_api_key`，重试沿用快照 ID、候选集合摘要、Lens、Prompt 和模型版本，只重试未完成批次。本地完整 F 层回放优先于模型请求；Agent 失败不改变候选集合。

`exploratory` Agent 的新候选只能进入 `exploratory_candidate_proposals` 的 `pending_human_review` 队列。建议必须绑定代码、提议 Lens、来源运行 ID、当前快照、合法事实引用、理由和缺失证据；Qt 的正式复核必须由 `human:<id>` 或 `user:<id>` 使用原始快照重新通过 CandidateLens。复核通过后才生成正式 CandidateLens 候选，仍需另一个明确人工动作才能进入 `watch`。

### 阶段 4：轻量研究台

已落地研究侧隔离入口：`research/research_workbench.py`。

- 只编排 `research/` 内已有数据处理、因子诊断、回测分析、v2 shadow 和 oracle crosscheck，不接入商业主链路。
- Qlib、Lean、FinRL-X、OpenBB、vectorbt/backtesting.py 只作为架构或方法参考；OpenBB、vectorbt、backtesting.py 等许可证风险依赖不得进入主 `requirements`、PyInstaller spec 或商业包。
- 研究台输出只能作为候选配置、解释或研究报告，不能直接修改 CandidateLens 候选、排序、F/G 层状态或人工观察状态；旧 shadow/公式结果只作为 legacy 兼容记录。
- 研究台新增 `template_diagnostics.py`：保存八模板候选池两两重叠、参数尝试的全部记录和结果指标字段；holdout 不参与参数选择。
