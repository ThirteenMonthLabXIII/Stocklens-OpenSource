## API Key 验证

设置页保存 API Key 后自动后台验证，避免阻塞 Qt 界面：

- OpenAI：`GET https://api.openai.com/v1/models`。
- DeepSeek：`GET https://api.deepseek.com/models` 和 `GET https://api.deepseek.com/user/balance`。
- 验证状态包括：未填写、正在验证、验证通过、Key 无效、余额不足、请求过快、网络异常、模型可能不可用。

Qt 工作台设置页主按钮固定为“保存并验证”，次按钮为“重新验证连接”；保存后仍自动验证 API Key，界面不得明文展示敏感 Key。

项目不再包含授权生成工具或 `stock_tool/core/license.py`。`private_keys/`、`.pem`、`.key`、`license_private_key.json` 仍被 `.gitignore` 和第九阶段交付脚本排除，防止历史敏感材料误入包。

## 风险提示

1. 免费公开数据接口可能变化，正式销售前仍需持续做行情源监控和接口容错。
2. live 小样本受网络、代理、防火墙和公开接口限流影响，失败只记录风险，不阻断离线发版。
3. AI 输出必须保持“数据分析和复盘辅助”定位，不应输出直接买卖建议。
4. API Key 若使用数据库兜底，售后排查前必须提醒客户清空或打码。
5. API Key 若验证失败，AI 功能调用仍会在实际请求时给出二次错误提示，最终扣费和额度以服务商控制台为准。
6. 当前未配置 Windows Authenticode 发布者证书；Cosign 可验证候选完整性，但 Windows 安装提示仍可能显示“未知发布者”。

## 东方财富限流保护

东方财富 HTTP 请求统一经过 `data_fetcher._eastmoney_get()`：串行最小间隔、少量随机抖动、Keep-Alive 会话、镜像节点轮询和有限重试。逐只主力资金首选历史日线端点 `fflow/daykline/get`，避免实时推送端点只返回当日一行导致 3/5/10 日窗口退化。

`requirements-optional.txt` 中的 `adata`、`efinance` 只作为可选第三方兜底源；核心安装和商业包默认依赖不包含它们。兜底源只在东方财富网关失败后尝试，且复用同一节流闸。

## 资金流 3a/3b 收口

智能筛选“主力进场”默认使用 `market_money_flow()` 的东方财富 f164 批量 5 日主力净额；个股详情和观察任务使用逐只历史 `fflow/daykline/get`，必要时降级到腾讯当日值。免费主链路不依赖 Tushare token，也不消耗 AI token。

3a 固定为离线验收结论：`3a PASS：逐只 money_flow 多日窗口离线回归通过。` 验收命令为 `python -m compileall stock_tool tools`、`python tools\test_money_flow_window.py`、`python tools\test_all_blocks.py --full`。`tools\check_money_flow_live.py` 仅作人工 live 风险核对；东方财富限流、网络或代理失败不改变 3a PASS 结论。

3b 当前口径：东方财富 f164 仍是资金流主链路；Tushare `moneyflow_dc` 仅作为客户自带 token 且在设置页打开“东财资金流失败时启用 Tushare 兜底（需 token/积分）”后的增强兜底。启用后也只在东财批量资金流失败、且 15 分钟新缓存和 1 天内旧缓存都不可用时尝试；成功后写入同一个 `market_money_flow` 缓存，失败则继续忽略主力条件，不阻断筛选。`moneyflow_dc` 的 `net_amount` 单位为万元，代码中统一乘以 `10000` 转为元后再进入筛选口径。无 token、未开启、权限/积分不足、字段缺失或行数过少都只是降级原因，不当成软件故障。

可选 live 检查：`python tools\check_tushare_moneyflow_fallback.py` 使用生产同款 HTTP 聚合逻辑验证 token/权限/5日聚合；无 token 时成功退出，不进入离线完整体测试。

## 免费行情准实时价格预警

Qt 必须经 `AlertMonitorCoordinator` 调用预警状态机：它统一交易日/时段、覆盖股票数、有效间隔、腾讯主源/新浪补源的批量快照、新鲜度、退避、状态提交和下一次单次调度。UI 不得逐条调用 `quote_by_code()` 或直接调用 `AlertService.check_alerts()`。

- 时间均使用 `Asia/Shanghai`，有效区间为 `[09:30, 11:30)`、`[13:00, 15:00)`；午休下一次固定为 13:00，收盘后下一次为下一交易日 09:30。
- 新安装默认 30 秒；既有 `1/5/10/30` 分钟配置迁移为原秒数，不擅自缩短。覆盖唯一股票数 1–10、11–30、31+ 的最低间隔分别为 15、30、60 秒。
- 日历加载异常、空结果、结构异常或缺少目标月份时返回 `calendar_unavailable`；自动和手动检查均在行情入口前返回，不请求行情、不提交状态机、不写历史、不发通知，监控保持启用并在 5 分钟后只重试日历。已知非交易日自动检查跳过，手动检查仍可做只读快照预览。
- 新鲜度使用 `age = now - quote_at`，只接受当前交易日且 `0 <= age <= 120` 秒；缺少真实行情时间、跨日、未来或过旧快照只显示旧行情，不触发、不更新边沿状态。非交易时段的手动检查是只读快照预览。
- 整批没有可用新鲜行情时，自动检查按 60/120/300 秒退避；部分代码失败不会触发整批退避。SQLite 原子认领确保多开软件最多产生一条历史和一次通知。

## 本地自动复盘

`stock_tool/core/review_automation.py` 是 Qt 之外的唯一自动复盘编排入口。它不创建行情客户端，接收 UI 传入的 `quotes_by_codes()` 行情提供器和 `PriceSource`，依次执行：上海时区最近完整交易日解析、SQLite 运行权抢占、开放观察任务批量检查、到期样本结算和运行报告写回。

- `review_automation_runs` 位于工作台账库，使用 WAL、30 秒 busy timeout、部分唯一索引和 owner token；超过 30 分钟无心跳的运行会被启动补偿接管。
- 交易任务只接受当日、非未来且不超过 120 秒的真实 `QuoteSnapshot.quote_at`；缺失或过旧行情保持任务进行中。
- 价格窗口、基准和行业数据裁剪到 `effective_asof_date`。`missing_price` 第 1/2/3 次分别按 1/5/15 分钟重试，之后才写终态无效 outcome；`missing_benchmark`、`missing_industry` 不进入有效绩效样本。
- Qt 页面会显示启停状态、上次运行、有效业务日期、待处理数量、有效/无效结算和下次调度；软件关闭期间不运行，重启后自动补偿。该功能只用于研究和复盘辅助，不产生买入/卖出建议，也不改变候选资格、排序或人工观察状态。
- Windows 登录后无人值守入口：`powershell -ExecutionPolicy Bypass -File tools\register_review_automation_task.ps1 -ExePath <exe> -DryRun`；确认目标后去掉 `-DryRun`，删除使用 `-Unregister`。
- 所有 UI smoke 与真实点击测试传入 `MemoryNotificationChannel`，不得调用真实 Windows Toast。预警历史和 CSV 包含“数据源”“行情时间”。
