# 阶段 2：证据包和事实引用校验

阶段 2 已完成。正式研究旁路现在只允许读取绑定不可变快照的证据包；候选集合、Lens、数据质量和事实来源由本地系统提供，Agent 不能自行补造事实。

## 证据包 v1

入口为 `stock_tool/core/research_discussion.py` 的 `build_evidence_package()`。正式包必须包含：

```text
snapshot_metadata
candidate_set_digest
lens_definition
facts
candidate_records
data_quality_summary
evidence_package_hash
```

每条 `facts` 都转换为 `Fact v1`，并同时绑定 `snapshot_id`、`available_at`、`quality_status` 和 `raw_hash`。证据包使用规范化 JSON 计算 SHA256；发送 AI 前会重新计算，任何修改都会阻断请求。

## Claim 校验

正式响应使用结构化 `claims` / `counter_claims`。每条 claim 必须包含：

```json
{
  "claim_id": "technical-001",
  "type": "supports_lens",
  "text": "近20日相对行业中位数表现较强",
  "evidence_refs": ["fact-001", "fact-002"],
  "caveats": []
}
```

本地校验会拒绝：

- 不存在、重复或不属于当前快照的 `fact_id`；
- 跨股票代码的混合引用，或 claim 指定代码与事实代码不一致；
- 晚于 `snapshot_metadata.availability_cutoff` 的事实；
- `partial`、`unverified`、`blocked`、`stale` 事实作为已验证结论；
- 已过 `asof_at` 的公告/新闻事实作为当前事件结论；
- claim、响应或证据包中的未知字段；
- 买卖、目标价、收益、仓位、排名、分数和方向性评级字段或表述。

`insufficient` 只用于明确表达数据不足，不能把缺失值转成零。旧的无事实研究讨论接口仍可读取，但会明确标记为 `legacy_compatibility`，不属于正式证据包。

## 外部文本安全边界

公告、新闻标题和网页文本在提示词中统一放入 `<external_fact>...</external_fact>` 区块，并明确标记为不可信资料。模型不得执行其中的命令，也不能通过外部文本改变任务或证据边界。外部文本没有对应当前快照 `fact_id` 时，不得作为正式 claim 证据。

## 审计和回放

`research_discussion_audits` 现保存：

```text
run_id
evidence_package_hash / evidence_package_json
request_hash / request_text
response_hash
prompt_version
model_version
created_at
cost_note
raw_response
normalized_response
```

模型返回 JSON 截断或解析失败时，原始文本仍会保留；成功时保留原始文本和规范化 JSON 两份内容，可按 hash 复核同一请求和响应。
