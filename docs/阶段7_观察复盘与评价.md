# 阶段 7：观察、复盘和评价

## 1. 验收结论

阶段 7 的离线实现已完成，评价链路不参与候选资格、排序或人工观察状态，也不把 AI 置信度当作表现指标。正式表现仍由既有 `PerformanceStore` 负责，但读取时严格限定 `sample_class = formal`；`review_only`、`exploratory` 和历史 `legacy` 单独统计。专业公式仅作为历史兼容数据读取，不进入新候选、F/G 层或正式绩效。

本阶段不改变 V1 schema version（仍为 16）。新增的 `observation_evaluation_exclusions` 是懒创建的附加表，旧数据库可以读取；旧的观察样本和 outcome 表继续作为事实来源。

## 2. 三类评价存储

### ObservationOutcomeStore

- 把 `formal`、`review`、`exploratory`、`legacy` 映射为四种评价模式。
- 统一读取样本、结算 outcome、Lens ID、Lens 版本、市场状态和快照 ID。
- 缺价格、缺基准、缺行业、过期/不可验证、未结算和人工关闭均保留原始样本，并生成排除原因。
- `human_closed` 必须由 `human:<id>` 或 `user:<id>` 写入；无人工 actor 的写入会被拒绝。
- 产品名称改变不会改变 sample ID、run ID 或 Lens ID，因此不会取消历史评价。

### DataQualityEvaluationStore

评价：

- 最新快照年龄；
- 字段缺失率（只有质量摘要同时提供 expected/missing 分母时计算，否则显示不可计算）；
- 数据源稳定率；
- 事实集合摘要可复现率（重新根据当前事实集合计算 `facts_digest`，不只检查摘要字段是否存在）；
- 缓存/备份使用率；
- failover 使用率；
- 事实修订率。

### AgentEvaluationStore

从 `formal_agent_run_history` 和 `formal_evidence_runs` 读取正式五 Agent 的持久化记录，统计执行成功率、超时率、JSON 合规率、证据引用有效率、不支持声明率、覆盖率、冲突数、延迟和费用记录。费用只读取已有费用说明；没有费用说明时计为缺失，不填估算值。`AgentExecution` 现在保存 `latency_ms`。缺 Key、失败、超时和部分失败只影响 Agent 过程状态，不改变 CandidateLens 候选集合。

### LensEvaluationStore

按 Lens 和 3/5/10/20 日周期统计：样本数、有效结算数、样本覆盖率、收益、相对 HS300 超额、相对行业超额、平均/最差回撤，并提供市场状态分组和按日期排序的 70/30 样本外稳定性结果。有效表现只使用 `data_quality = ok`、已结算且未被排除的样本。

行业相对收益由 `StoreBackedPriceSource` 在 PIT 行业成员和 PIT 价格均可用时按成员等权计算；行业成员不足或价格不足时返回缺失，样本进入排除统计，不伪造行业超额。

## 3. Qt 验收面

“观察与复盘”新增“系统评价”页签：

- 可选择四种评价模式；
- 显示数据质量和正式 Agent 过程指标；
- 展示 Lens、版本、周期、覆盖率、平均收益、HS300/行业超额、最差回撤和样本外状态；
- 明确提示：正式、复核、探索和历史兼容样本分开；不使用 AI 置信度替代表现评价。

## 5. 边界与后续数据条件

- Agent 过程评价当前只对正式 Agent 持久化记录统计；复核/探索流程没有正式 Agent 执行信封时不会被虚构成成功或失败。
- 字段缺失率依赖刷新质量摘要提供分母；缺分母时必须显示不可计算，而不是显示 0%。
- 行业相对收益依赖 PIT 行业成员与未来结算价格；PIT 数据不完整时只产生 `missing_industry`，不进入有效 Lens 统计。
- 样本外稳定性至少需要同一 Lens、同一周期 4 个有效样本；不足时明确显示样本不足。
