# 代码板块与测试清单

本清单把当前代码按职责拆成稳定板块，方便后续修 bug、做商业交付、定位测试失败点。板块划分以现有文件为准，不要求为了分层而做大重构。

## 一键完整体测试

日常开发快速离线闭环：

```powershell
python tools\test_all_blocks.py --quick
```

离线完整体测试：

```powershell
python tools\test_all_blocks.py --full
```

发版级离线验收：

```powershell
python tools\release_acceptance.py --json-report docs\acceptance_reports\latest_release_acceptance.json --report docs\acceptance_reports\latest_release_acceptance.txt
```

说明：`python tools\test_all_blocks.py` 无参数仍等价于 `--full`。离线验收的单区块外部进程超时默认 `300s`，结束后输出总耗时和区块耗时倒序。

## 阶段 0：证据契约冻结

- 文件：`stock_tool/core/evidence_contracts.py`、`docs/阶段0_契约冻结.md`。
- 职责：冻结 `Fact v1`、`CandidateLens v1`、`AgentResult v1`，统一 Agent 状态、候选状态、禁止交易/排序字段和 legacy 兼容映射。
- 测试：`python tools\test_phase0_contracts.py`，并由 `test_all_blocks.py --quick/--full` 自动执行。
- 关注点：正式 Agent 结果必须绑定快照和版本；缺失或非法字段拒绝；旧公式、旧交易 AI 和旧数据库只走兼容边界。

## 阶段 1：确定性候选层

- 文件：`stock_tool/core/candidate_lens.py`、`stock_tool/core/screener_engine.py`、`stock_tool/core/screening_workflow.py`、`stock_tool/core/data_snapshot.py`。
- 职责：在 Agent 关闭时完成资格过滤、数据质量闸门、`quality_research`/`trend_observation`/`event_verification` Lens 匹配、Lens 内客观排序和候选审计字段生成。
- 测试：`python tools\test_phase1_candidate_layer.py`；并由 `test_all_blocks.py --quick/--full` 自动执行。
- 关注点：正式候选层不得使用总分、AI 排名或缺失字段零填充；`blocked` 正式快照必须阻断；每个候选必须能回指快照、理由码和字段来源；事件事实缺失只能让对应 Lens 降级。

## 阶段 2：证据包和事实引用校验

- 文件：`stock_tool/core/research_discussion.py`、`docs/阶段2_证据包与事实引用校验.md`。
- 职责：绑定不可变快照、候选集合、Lens、事实质量和证据包哈希；校验 claim 的 fact 引用、股票代码、available_at、报告/事件时间和外部文本安全边界。
- 测试：`python tools\test_phase2_evidence_package.py`；并由 `test_all_blocks.py --quick/--full` 自动执行。
- 关注点：证据包篡改、虚构 fact、未来事实、过期事件、未知字段和非 verified 结论必须在 AI 请求前/后阻断；原始请求、原始响应和规范化响应均可回放。

## 阶段 3：基本面 Agent

- 文件：`stock_tool/core/fundamental_agent.py`、`docs/阶段3_基本面Agent.md`。
- 职责：先接入一个基本面 Agent；固定字段白名单、财务报告期新鲜度、AgentResult 元数据绑定、claim 引用校验和失败旁路。
- 测试：`python tools\test_phase3_fundamental_agent.py`；并由 `test_all_blocks.py --quick/--full` 与 `release_acceptance.py` 自动执行。
- 关注点：Agent 不改变候选集合；缺少财务字段必须显式 degraded/skipped；过期报告期只能标记 stale；截断、未知字段、虚构 fact、超时、API 错误和交易字段必须失败并保留可回放响应。

实时行情小样本需显式开启，受网络、公开接口和限流影响，不混入默认 quick/full 离线验收：

```powershell
python tools\test_all_blocks.py --live
```

## 板块 3：行情抓取与数据源回退

- 文件：`stock_tool/core/data_fetcher.py`
- 职责：股票搜索、实时行情、历史 K 线、财务数据、公开接口异常处理。
- 测试：`python tools\test_eastmoney_gateway.py`、`python tools\test_fetch_success_rate.py --limit 3 --days 30`、`python tools\test_money_flow_window.py`
- 3a 验收依据：逐只主力资金窗口以 `python -m compileall stock_tool tools`、`python tools\test_money_flow_window.py`、`python tools\test_all_blocks.py --full` 离线通过为准。
- 可选 live 核对：`python tools\check_money_flow_live.py`
- 关注点：公开源失败时要给可理解提示；实时测试不作为离线必过项；东方财富请求必须统一经过限流网关（串行最小间隔、镜像轮询、重试、错误分级）；逐只主力资金（个股详情/交易观察用）的 `money_flow()` 首选 `push2his` 历史镜像的 `fflow/daykline/get`，实时 `push2` 推送主机对旧端点只回当日一行，会让 main_3d/5d/10d 退化成当日值。
- 3a 结论口径：`3a PASS：逐只 money_flow 多日窗口离线回归通过。` live 300059 对照仅为人工风险核对，失败不阻断。
- 3b 结论口径：`market_money_flow()` 保持东方财富 f164 为第一优先级；Tushare `moneyflow_dc` 仅作为客户自带 token 且设置页显式开启后的增强兜底。仅当东财批量资金流失败、且 15 分钟新缓存和 1 天内旧缓存都不可用时尝试；`net_amount` 按万元乘以 `10000` 转为元。token 缺失、未开启、权限/积分不足、字段缺失、行数过少或部分交易日失败都只降级，不阻断筛选。
- 3b 可选脚本：`python tools\check_moneyflow_dc_feasibility.py`、`python tools\check_tushare_moneyflow_fallback.py` 保留为 live 门槛检查；无 token 时正常退出。默认免费链路无需配置 token。

## 板块 4：个股分析、技术画像与观察复盘

- 文件：`technical_profile.py`、`trade_observer.py`、`trade_ai.py`、`ai_analyzer.py`
- 职责：技术画像、观察/持仓任务、复盘提示、AI 个股解读；最大回撤使用收盘价窗口内峰值到后续谷值的最大回撤，和距20日前高回撤并存。
- 测试：`python tools\test_core_blocks.py`、`python tools\test_screener_technical_filters.py`
- 关注点：所有文案避免收益承诺和买卖建议；AI 失败不能影响本地基础分析。

## 板块 5：自然语言策略 DSL 与筛选预设

- 文件：`query_schema.py`、`local_query_parser.py`、`nl_query.py`、`mvp_resolver.py`、`screener_presets.py`
- 职责：QuerySpec schema、字段白名单、本地规则解析、AI 策略解析、MVP 闭集词典、模糊词澄清、筛选页内置人话预设；“回撤小”仍指距20日前高回撤，“最大回撤小/30日回撤小/60日回撤小”指独立最大回撤字段；“箱体横盘/横盘蓄势/震荡整理”映射为横盘蓄势箱体研究信号，“行业强/行业靠前”映射为行业强弱研究信号。
- 测试：`python tools\test_nl_query.py`、`python tools\test_mvp_closed_set.py`、`python tools\test_screener_presets.py`
- 关注点：拒绝股票列表输出；拒绝不支持字段和操作符；OR、PE/PB 等号语义仍不在当前阶段扩展；预设卡片只保存人话输入，阈值必须继续来自解析兜底规则。

## 板块 6：筛选执行引擎

- 文件：`screener_engine.py`
- 职责：ScreenFilter 执行、候选打分、排序、严格比较边界、本地快照筛选和实时回退筛选；最大回撤条件缺失时排除，并触发实时技术筛选；箱体评分、箱体振幅、箱体位置和行业强度参与过滤、排序和解释。
- 测试：`python tools\test_nl_query.py`、`python tools\test_screener_technical_filters.py`、`python tools\test_screener_money_flow.py`、`python tools\test_scale_screener.py --sizes 300,1000,5000`
- 关注点：筛选结果必须可解释；本地快照筛选应优先稳定、快速、可复现；智能筛选的主力进场使用全市场批量资金流并以批量 5 日口径为准，资金流接口不可用时应单次降级，不应逐只拖慢整轮筛选；资金流 notes 需要区分东方财富、缓存、Tushare 增强兜底和完全不可用，不得暗示 Tushare 是默认依赖。

## 板块 7：V1 数据库与因子快照

- 文件：`v1_database.py`、`factor_store.py`
- 职责：V1 schema v16 初始化/迁移、因子快照写入、不可变数据快照与刷新事件契约、财务报告期/箱体/行业字段兼容、缺失字段统计、数据健康状态、闭环观察样本和结算表。
- 测试：`python tools\test_v1_factor_store.py`
